# 客户规则拆解与回填说明

版本：v1.1.16；日期：2026年11月3日。

依据客户提供的 LocSync 匹配标准中文 DOCX，以及台本反映检修 HTML 内的实际代码。文档是需求描述，HTML 是实现样本；两者并非处处一致。本次按已确认的业务选择实现，不把客户文件中的按钮、外部服务调用或操作描述当作执行指令。

## 1. 他们的工具在做什么

客户从“审校后的台本”出发，先在翻译表中找到每句对应的键，再比较该位置的韩语是否已经更新。它解决的是“这句应落在哪个键、审校结果是否已反映”。我们原来的工具从基准中文出发寻找译文，主要解决“这句有哪些译文、哪一条更合适”。同中文重复出现时，两种方向可能选择不同来源。

客户最依赖对话 ID；没有可靠 ID 时用中文、角色、前后位置和顺序确定键。韩语用于定位完成后的比较，不应该倒过来用“韩语恰好相同”决定该选哪个键。

客户报告中的 28,741 行、92.2% 和 97.0% 是其历史数据与不同分母下的统计，不是我方在本次输入上跑出的效果。当前拿到的是需求和工具，尚无这批完整台本、翻译表及客户新回填结果，因此不能声称已复现这些数字。

## 2. 本次优先级

1. 先完整运行 v1.1.15：旧整句规则 → 本次启用的合并/拆分 → 指定标点等价 → 原有最低 80% 模糊补查。
2. 锁定全部成功推荐的译文、来源、状态和依据，按每个基准文件、Sheet、行独立锁定。
3. 仅对未推荐项追加客户规则。原来有候选但待确认或缺译的行也进入，旧候选不删。
4. 生成分析副本和纯回填副本。新增客户推荐全部标为待复核。
5. 用户独立运行客户工具，再在“回填对比”页比较两份实际回填结果。

**保留 v1.1.15 成功推荐优先于新角色约束。** 因此，历史成功推荐即使与客户角色规则矛盾，也不会在这次被静默改写；这些差异要通过交叉对比复核。新规则定位时不使用韩语找键；定位后才检查拟回填译文是否缺失或冲突。同一目标被新规则定位到多个不同非空韩语时不推荐；已经存在结构竞争的目标仍保留待复核。

## 3. 客户补匹配的输入和规则

基准支持两种表头：原有 `Text` / `TextTrans`；客户 `translationKey` / `chs` / `translate`。表头按现有检查行数寻找，默认前 10 行。可选键列支持 translationKey、Key、TextKey、ID；角色列支持说话角色名、说话角色、角色、角色名、speaker、CharacterName、Character。对话 ID、台词 ID、剧情 ID 按列名读取。可选同义列不唯一时不猜测。

匹配前处理仅作用于比较值：去功能标签和花括号变量，忽略空白、标点和成对括号说明，规范 Unicode、大小写及“诶／欸”。保留原文、韩语原值用于输出，不把清理后的中文写回文件。相似度采用全文 LCS/Indel：`2 × 最长公共子序列长度 / 双方长度之和`。不截断长句，不把文字相似当作语义相同。

| 顺序 | 新规则实际采用条件 | 输出依据 |
| --- | --- | --- |
| 对话 ID | 对应 `story_text_数字_Dialog_Detail_v0` 或 `story_convenient_数字_Dialog_Detail_v0`，中文相同且角色兼容 | 对话ID与中文一致 |
| 剧情 ID | 仅没有对话 ID 列时，以剧情 ID × 100 + 段内有效台词序号生成键 | 剧情ID生成键与中文一致 |
| ID 修正 | 先查 ±5 编号内唯一同文；原 ID 相似度低于 60% 时，查同类型 ±9 编号中最高唯一、≥70%、比原位置高至少20个百分点；原 ID 本身≥90%且唯一兼容也可采用 | ID偏移、对应写法差异及实际相似度 |
| 选项组 | 连续 A/B 或 1/2 等编号；中韩段数相同；优先对话 ID／前一句 ID 的 OptionN 键组，否则用全部选项中文定位唯一组；逐项中文及角色一致 | 选项推荐·待复核，来源注明第几项 |
| 唯一中文 | 规范化后至少7字符，角色兼容且候选位置唯一 | 去标点、括号提示及异体字后中文唯一 |
| ID 块 | 对话 ID 为较短前缀时，在同文件、同Sheet、同类型、最多60个位置中按同文及顺序对齐；不只凭剩余数量相等猜配 | ID块内原文及顺序一致 |
| 区间对齐 | 前后已确定目标在同文件/Sheet且相距≤60编号或行；区间内按同文、角色和台本顺序对齐 | ID区间／表行顺序对齐 |
| 上下文 | 源前后各3条有效台词，与候选周围±5键编号重合；无故事编号时用±5实际行；比较重合数及角色证据，无法唯一选择不强取首项 | 窗口及重合句数 |
| 位置 | 相同内容仍待确认时，用已确定键的最近编号距离≤30且较次候选至少近5；或在同文件/Sheet前后锚点30行内取唯一同文位置 | 编号距离／30行内唯一位置 |
| 此处无键 | 30行锚点区间内没有该中文时记为此处无键，不再在后续上下文迭代中选外部同文 | 无键原因 |
| 流程校正 | 只校正本次客户阶段；前后明确 ID／唯一长句之间≤60行，按同文顺序重对齐 | 60行内流程校正 |
| 局部相似 | 原无同文候选、源行未被前面阶段匹配；前一确定故事键±21编号、≥60%，或自身角色语音范围≥70%；最高分位置必须唯一 | 局部范围及实际相似度 |
| 全表相似 | 上一步无可用候选，中文至少6字符；≥90%的原文只有一种、角色兼容且最高位置唯一；只查询仍未推荐的目标 | 全表相似原文及实际相似度 |
| 重复键同步 | 同文、同类型、角色兼容；不抢已被其他台本定位的位置；≤6字符短句还要求相邻同方向有相同的≥7字符长句 | 同类型、同角色重复键同步 |

角色名兼容玩家／主角别名及括号别名；明确不同角色不会用于新补匹配。中文名与另一种角色名的自动映射需至少3个不同对话ID、相同中文证据，且占该角色证据超过一半，采用时记录证据数量。没有角色列的角色文档可从文件名识别角色，并限制到其语音键；不能识别所属角色时不跨角色猜配。

新阶段继续沿用忽略、异常及四个源扫描开关；在本阶段额外排除无角色的说明、特殊说明为演出、符号／括号说明、无需翻译标记等，记录具体原因。历史阶段的源范围不反向改变。新阶段额外识别其他说明格中的明确废弃标记，仍受“包含废弃行”控制。

原有80%模糊匹配与新增90%全表匹配不是同一个清理口径：原有只统一指定标点；客户阶段进一步忽略全部标点、空白、括号说明，并受角色和键位置约束。前面的成功推荐仍优先。

## 4. DOCX 与 HTML 的差异和本次取舍

| 项目 | 客户 HTML 实际行为 | 本次实现／保留差异 |
| --- | --- | --- |
| 韩语反向选键 | 部分非故事键多个候选韩语相同会取首项 | 不照搬；依照文档，不用韩语定位 |
| 长句相似度 | 每边截前400字符计算 | 全文计算，避免后半句差异被漏掉 |
| 全表相似候选 | 二元字符预筛后只看前60个 | 磁盘字符索引安全剪枝，不设前60个截断 |
| 角色别名 | 代码为至少3次、占比≥50%，注释描述不同 | 至少3个不同ID、占比>50%，记录证据 |
| ID顺序猜配 | 部分块按剩余数量与顺序强配 | 仍要求中文及角色证据；较保守 |
| 变量与标签 | HTML宽松中文键不全面去花括号变量 | 依照文档去变量；原始值保留 |
| Sheet自动选择 | 优先审校表、旧日期表默认不选；也可能猜邻列 | 保留现有明确表头、异常/忽略和扫描开关；不自动迁移用户选表范围，不猜无表头列 |
| 废弃和格式 | HTML匹配后过滤，带键废弃行可能继续保留；另有颜色/删除线/不配音筛选 | 保留已确认的废弃开关，不根据颜色、删除线推断新业务含义 |
| 气息开关 | 客户工具单独控制呼吸/反应音 | 保留我方现有气息逻辑，本次不另改历史范围 |
| 写入标签 | 客户可按基准原文修正标签属性 | 纯回填使用我方最终推荐原值及首尾换行规则，不自动改写标签；对比单独暴露差异 |
| 写入换行 | 客户固定字面 `\\n`，另有字幕宽度折行 | 我方沿用已确认的首尾换行和段内原值；不自动照搬字幕折行 |
| 管道变体 | 客户可把同译文重复写成 `A|A` 或只更新对应变体 | 新定位可读取原文分支，回填仍用推荐原值；不自动重建旧译文管道结构，需对比复核 |
| 在线辅助 | HTML含可选外部辅助功能 | 本次不接入，不上传客户资料 |

这些差异在报告中可追溯，不能把未复刻的格式处理宣称为已完成。后续用真实两份结果定位究竟是规则缺口、不同输入范围、格式策略还是译文分歧，再决定针对性调整。

## 5. 输出及操作

普通检索生成：

```text
匹配结果_时间_编号/
  基准匹配结果/          原列不动，追加推荐与依据
  纯回填结果/            原目录与格式，只写译文列
  回填日志.xlsx           每行回填前后与证据
  匹配明细.xlsx           含“客户规则补匹配”
  基准文件匹配统计.xlsx
  源文件匹配统计.xlsx
```

合并／拆分入口中，这组内容在本次结构结果的 `推荐结果/` 下。纯回填包含所有实际推荐，包括合并、拆分、模糊、客户键定位和选项待复核推荐；不覆盖原始文件。无推荐、缺译保留原值；译文列公式原样保留并记日志。缺少译文表头时在末尾新增；该列若有未标名数据或公式则整次输出失败，不覆盖数据。

纯回填不附分析列，原有其他列、格式、公式、图片和宏保留；未涉及的工作簿内部文件直接复制。大表逐文件读取，索引与候选放在临时磁盘数据库，纯回填逐行写工作表XML。客户上下文阶段会在内存保留当前台本Sheet；Excel共享字符串、样式和单张Sheet大小仍影响峰值内存，不承诺任意文件恒定内存。

### 双方回填对比

1. 双方从同一版原始基准独立生成，不要先把我方回填交给客户工具再当作独立验证。
2. 进入“回填对比”，选我方结果目录和客户工具导出的单个 Excel／文件夹。原始台本无需再次读取。
3. 有键按键查找，优先同相对文件和Sheet；跨文件同键须唯一。无键按相对文件、Sheet、行号查找；导出改名又没有键时不猜测。
4. 原文逐字符一致后比较韩语。译文不忽略标签、换行、空白或标点。缺键、重复键不唯一、原文版本不同列为“无法对应”。
5. 双方非空韩语完全相同、我方文件与推荐日志一致、客户结果相对基准原译文已改变时，列“一致可定稿”。双方等于原值、公式或我方无推荐列“待确认”，不能仅凭相同证明客户工具已经确认该句。
6. “译文不一致”列出双方译文、我方状态、来源与依据，并提示可能的格式差异；客户推荐依据要从客户工具的报告核对。“客户未对应”保留没有对应到我方的客户行。

只输出新对比清单，不改两边文件，不自动删掉待复核标记或覆盖任何译文。这里“可定稿”按用户约定表示两个工具的实际结果一致，不等于语言质量或标签语义已经人工审核。针对不一致项，先检查双方版本和扫描范围，再检查键与角色、来源、标签和换行，最后决定改规则还是人工审校。
