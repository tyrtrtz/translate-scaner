# 中韩表头检查与译文检索

第一步检查客户源文件的中韩表头，列出异常供客户处理；第二步按基准中文检索译文，输出基准匹配副本和源文件匹配率统计。源文件和基准原件均不会被修改。

## 使用

安装 Python 3.10 或以上（需包含 Tkinter），在项目目录运行：

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

Windows 开发环境将前两条替换为 `py -3 -m venv .venv` 和 `.venv\Scripts\activate`。

选择 **1_客户源文件**，不要选择同时包含基准文件的上级目录。根据需要调整表头名称和检查行数，点击“开始检查”。双击异常项（或选中后按 Enter）可查看可滚动的检查依据，包括允许的表头名称、已找到的位置、顶部及候选表头行的实际文本样例，以及同文件中已通过的工作表。也可打开所选文件所在文件夹。点击“导出异常清单”保存 CSV，Windows Excel 可以直接打开，中文和韩语采用 UTF-8 BOM 编码。

## 批量忽略 Sheet

在“异常列表”最左侧点击方框逐项勾选，可直接选择不相邻的 Sheet，也可以点击“勾选全部”或“取消勾选”，然后点击“忽略勾选 Sheet”。查看、双击其他行不会改变已有勾选；键盘聚焦某一行后按空格也可以切换勾选。保存成功后，这些 Sheet 立即从当前异常列表、异常数量和导出清单中移除；后续检查在表头检查之前直接跳过它们，不生成错误，也不计入通过数量。源文件及其中的 Sheet 不会被修改。

“已忽略列表”显示本机保存的所有忽略记录，也支持逐项勾选、勾选全部和取消勾选。点击“移除勾选忽略记录”后，重新检查即可恢复处理这些 Sheet。恢复时会清空旧检查结果，避免导出仍然缺少这些 Sheet 的旧清单。

忽略范围是 **文件完整路径 + Sheet 名称**，不影响其他文件里的同名 Sheet；文件或 Sheet 改名、移动后需要重新设置忽略。找不到 Sheet 名称的文件级读取失败或不支持格式记录不能按 Sheet 忽略。

记录会自动保存，重启程序仍然有效；界面“已忽略列表”中显示记录文件位置：

- macOS：`~/Library/Application Support/HeaderChecker/ignored_sheets.json`
- Windows：`%LOCALAPPDATA%\HeaderChecker\ignored_sheets.json`（没有 LOCALAPPDATA 时使用 APPDATA）
- Linux：`$XDG_CONFIG_HOME/HeaderChecker/ignored_sheets.json`，默认 `~/.config/HeaderChecker/ignored_sheets.json`

记录保存失败时保留原有列表，不会假装已忽略；记录文件损坏时明确提示并禁用检查，修复后重启，避免忽略设置静默失效。命令行入口也会读取同一份本地记录。

## 保存使用设置

源文件夹、基准文件夹、输出文件夹、自定义中韩表头、检查行数及四个扫描开关会在点击检查、点击检索和正常关闭窗口时自动保存，也可点击“保存设置”立即保存。重启后恢复设置，但不恢复旧检查结果，仍需先检查再检索。

设置保存在忽略记录同一目录下的 `settings.json`，与 `ignored_sheets.json` 分开，不影响已有忽略记录。采用临时文件加原子替换，保存失败或输入无效会提示，保留原有设置；设置损坏时使用默认设置并停用保存，明确提示修复文件后重启，不覆盖损坏原件。文件夹暂时不存在不会阻止启动，在检查或检索时再验证。

## 检查规则

- “包含子文件夹”“包含隐藏工作表”“包含隐藏行”三个开关默认开启。关闭子文件夹扫描时只处理所选目录第一层；关闭隐藏工作表扫描时不检查 hidden / veryHidden Sheet；关闭隐藏行扫描时不使用 Excel 标记为 hidden 的行，包括筛选后标记隐藏的行。表头行若被隐藏且开关关闭，也不会用于识别。忽略 Excel 的 `~$` 临时文件和非表格文件。
- “包含废弃行”默认关闭：在已识别的中韩表头同一行查找“特殊说明”列（列位置可变），正文单元格规范化 Unicode 并去首尾空白后恰为“废弃”的行不参与匹配、推荐上下文、统计和各类明细。勾选后包含这些行；没有该列时照常处理。“非废弃”等说明不作为废弃标记；存在多个特殊说明列时先提示确认，避免误选。特殊说明为公式且未勾选时需先转成文本值。改动开关后需重新检查。
- 第二步检索与源文件匹配率统计沿用第一步的四个开关；修改开关后需重新执行第一步。按开关跳过的隐藏 Sheet 不作为异常，但会列在匹配输出的“跳过清单”中。基准仍处理所有工作表和 Text 列文本行，表头位置按名称识别。
- `.xls`、`.xlsb`、`.ods` 会列为不支持格式，需客户转存为 `.xlsx`。
- 默认检查每张工作表前 **10 个实际行号**。行数输入框支持自行输入大于等于 1 的整数；不是前 10 个非空行，超出范围的表头需要增大行数后重新检查。
- 默认中文表头：对白文本、台词、文本内容（示例）、语音、最新(2.18)、中文原文；韩语表头：韩文、한국어、韩语译文。界面可增删名称，每行一个；设置会保存在本机。
- 采用完整名称匹配，忽略首尾空白并进行 Unicode NFKC 规范化，兼容全角括号和韩语组合字符。不猜测无表头的列，不按正文语言自动识别。
- 中文和韩语表头必须在同一行，且该行各有唯一候选列。找到多个共同表头行或候选列时列为异常。同一合法表头行之外的零散关键词不作为额外候选列。
- 尚未忽略的参考表、封面、修改记录等没有中韩表头时会列为“需确认是否为翻译表”，可在异常列表确认后批量忽略。异常数量不等于需要修改的翻译表数量。
- 文件损坏、加密或无法读取时列入异常，不会将其当作通过。某个文件失败不会阻止其他文件检查。
- 通过仅表示在指定范围内找到明确表头，不表示正文内容、译文质量或后续匹配已经验证。

异常 CSV 每项一行，包含文件名、相对路径、完整路径、工作表、显示状态、具体异常原因、中韩候选表头的位置、检查范围、检查依据和该文件已通过的工作表。无异常时导出只有列名的清单。

异常原因会区分缺少中文表头、缺少韩语表头、两者均未找到、检查范围内无非空内容、不同表头行和多个候选列。只缺少其中一种时会明确给出另一种的已识别位置。文本样例取顶部 3 个非空行及最多 3 个候选表头行，每行最多 32 项、每项最多 80 字；这是人工判断的证据，不意味着自动确认这些内容就是表头。未找到时只能说明检查范围内没有名称匹配，不能据此确定整张表没有译文或一定属于参考表。

## 大文件处理

逐个文件以 openpyxl 只读模式打开，只遍历指定的头部行，不加载图片，也不把所有正文汇总到内存。每个文件检查完成即关闭。共享字符串和样式仍可能占用内存，不承诺任意文件固定内存；根据客户样本实测。

## 第二步：译文检索

### 最后一轮模糊补查

整句匹配及本次启用的合并/拆分结束后，仅对仍属于“基准文件中找不到”的源句补查相似文本，最低相似度固定为 **80%**。目标限此前没有任何候选的基准位置；已有推荐、已有候选但缺译或冲突、结构竞争待确认的位置不参与。已使用、部分拆分使用及已有未写入结构推荐候选的源句不再进入；已推荐的同文同译重复来源也排除。源扫描开关、忽略和异常规则继续生效。

双方中文先沿用纯文本规则去掉标签、花括号占位符及实际/字面换行，并统一下述四组指定标点；保留其余文字、标点、数字和内部空格。仅数字、标点等不含文字的内容不参与。使用字符顺序相似度 `2M / (双方字符总数)`，M 为 `SequenceMatcher` 找到的相同片段字符数（基准在前、源句在后，关闭 autojunk）。以未四舍五入的得分判断阈值和并列，显示为一位小数百分比。磁盘索引先按长度及共有字符数筛选，再计算得分，不把全部句子两两载入内存。

达到阈值的候选全部保留。从非空韩语候选中选择最高分：最高分只有一种译文时写入推荐，同分同译取读取顺序首条；同分不同译文标为待确认，全部缺译则不推荐。一个源句仍可用于多个基准位置。成功状态为 **模糊推荐·待复核**，依据写明百分比；译文采用来源原值并沿用首尾换行对齐。字符相似不能保证语义相同，数字、否定词或短句变化需人工复核。

`匹配明细.xlsx` 可按“匹配方式=模糊匹配”筛选；末尾新增“基准中文”和数值型“相似度”，与“源中文”对照核查。该轮不使用上下文得分，相关文字为空、分数为 0，并注明未使用上下文。匹配、缺译、冲突及推荐统计同步计算；成功推荐的同文同译重复来源不再列入未推荐明细。

### 扫描合并与拆分候选

完成表头检查后，在“译文检索”页选择基准和输出文件夹，点击“合并/拆分并生成推荐”。“最多连续行数”默认 8，可调整为 2～50。完成后保留 `结构差异扫描.xlsx`、`试合并结果.xlsx`、`试拆分结果.xlsx`，并在本次目录的 `推荐结果` 中生成包含整句、合并和拆分推荐的基准副本、匹配明细与统计。“打开结果文件夹”“打开匹配明细”指向这次综合结果。

结构结果只补充尚无整句推荐的基准行，不覆盖 `TextTrans` 或已有整句推荐。推荐状态分别为 **合并推荐·待复核**、**拆分推荐·待复核**；可在基准副本中筛选。相同基准出现多组结构推荐时暂不选择，在“结构推荐未写入”中保留原因。普通“检索并生成结果”执行整句各轮匹配，再执行最后一轮模糊补查；合并/拆分入口在结构推荐后执行模糊补查。运行期间输入文件或范围改变时中止本次输出，须重新扫描。

结构预览在模糊补查前生成，“未解释”等预览数量不包含最后一轮模糊命中。最终采用情况以“推荐结果”的推荐列、匹配明细和统计为准。扫描不修改台本、基准原件或 TextTrans。报告包含：

- **合并候选**：仅针对基准 `char.xlsx` 中整句未命中的行，查找台本连续多行中文拼接后完整一致的所有候选，包含源译文、实际行号、邻句证据、缺译和候选译文冲突。
- **拆分候选**：基准连续多行能完整覆盖台本一格内容的候选，包含无明显分隔符的反查结果；分别说明中文分段边界、中韩编号及段数证据。
- **规则样本与规则汇总**：对所有参与台本的中文和韩文分别扫描字母/数字编号、全角半角标记、实际及字面换行。保留重复编号、混合格式、编号前文字和空分段，汇总次数、涉及文件数、异常数及可回查的样本ID。基准候选数只统计中文，韩文对应栏留空。
- **未解释**：既没有整句比较命中，也没有被结构候选覆盖的行；不将这些行判断为新增、缺失或错误。
- **原始内容、跳过清单与扫描说明**：保留全部参与行及原值，列出异常、忽略、排除范围及本次设置。过长的候选展示会明确提示回查原始内容。

比较文本仅去首尾空白，并忽略 `<color=#3266b4>`、`</color>`、`<b>`、`<size=20>` 等以英文字母开头的尖括号标签、实际换行和字面量 `\n` / `\r`；保留 `{playername}`、`%s`、`%d`、标点及内部空格。标签只在比较时忽略，报告原值和候选韩文仍保留标签供复核；格式扫描使用未清理的原文。结构扫描保留占位符，正式检索的纯文本补匹配则沿用去占位符规则。

源行排除规则与正式检索共用：同时存在“特殊说明”和“说话角色名”列且两列均为空时，整行排除；连续结构窗口不会跨过这些行。整句命中同时支持气息行去除成对括号说明，成功后记录双方行的覆盖情况，源行不会再误列为“未解释”。

连续窗口限同文件、同 Sheet、连续物理行，不跨空白、非文本、被排除的行或显式场景变化。可识别“场景”“场景名”“场景编号”中的唯一一列，沿用最近非空场景值；存在多个场景列会提示处理，没有场景列时不保证语义场景一致。每个窗口最多拼接 16,000 字符，超出范围的情况仍保留原始记录。邻句最多检查前后各三行，相同但重复出现的文本仅作为参考，不作为位置唯一的证明。

中韩段数相等、甚至编号一致，也不能证明译文语义对应正确。规则样本供归纳现有文件中的格式，不承诺穷尽所有拆分规则。结构推荐须复核后使用；单侧增删对齐不属于本次扫描功能。

试合并先沿用正式匹配的中文精确、纯文本及句尾去括号规则检查全部基准的整句命中，再仅对 **基准文件名为 `char.xlsx`（不区分大小写）且所有整句阶段均无中文候选**的行反查连续源行。限制针对目标基准文件，源台本仍按原范围读取；`story.xlsx` 和其他基准继续整句匹配及拆分扫描，暂不参与合并反查。没有读到 `char.xlsx` 正文时，合并结果为空，不扩大到其他文件。有中文候选但缺译或译文冲突的行，不当作“未匹配”，仍由正式匹配的上下文推荐流程处理。

`试合并结果.xlsx` 包含“合并建议”“全部反查候选”“复核填写”“整句命中检查”“合并范围”“流程统计与说明”。“合并范围”逐文件列出参与行数、整句命中及进入反查的数量；范围外行单独统计，不计入“反查仍无候选”。目前明确确认的合并样本来自角色必杀技分段台词；`char.xlsx` 的其他候选仍需按证据确认，不因文件名直接批准。

按源行顺序用一个空格连接去首尾空白的韩文，并补充句中省略号、叹号、句号后的空格。已有空白不重复补，最后句尾不补，小数、英文点分词、标签和占位符内部不改；每段原文、译文和来源位置仍保留。人工明确确认，或单一来源且具有双方全文唯一的连续邻句证据时，生成合并建议。多来源即使译文完全相同，也需要确认具体位置。源角色不一致、源角色与基准角色不同、跨剧情段或语音类型不同会判为不适用；缺译、占位符或标签异常仍暂不采用，人工确认不会跳过这些检查。只有标点、数字或占位符的内容也暂不采用。

允许同一组完整源行同时用于长句及只删去首尾完整源行的短句：每个目标都须只有一组来源，较短序列须严格等于较长序列的前缀或后缀。短句可生成待复核合并推荐，注明删去哪一侧的几条源台词；重复基准位置或非首尾嵌套的重叠仍视为归属冲突。若删减发生在单个源单元格内部，无法确定韩语边界，不按中文长度猜测截译；合并范围继续限于 `char.xlsx`。

报告追加角色、剧情段、语音类型、语音名、播放说明及基准条目信息。可选信息的公式或多个同义列显示为未知，不据此猜测角色或段落，也不会因此丢弃整张台本。语音名和播放说明供人工核对，不根据名称不同直接否决分段触发的语音。

后续复核只需在“复核填写”中修改“复核结论”和“复核意见”，结论填写 **可适用、不适用、待确认**。保存后在界面选择该复核文件，再扫描一次；也可使用 `--review-report` 参数。只读取明确结论，不把绿色等单元格颜色当作批准；“理论上可用”应填为待确认。导入成功后，结论保存于输出根目录 `合并复核记录.json`，界面清空复核文件选择，后续留空即可沿用记录。重新填写“待确认”或“不适用”可以撤回之前的确认，空白结论则不覆盖旧记录。

复核对应具体文件、Sheet、行号和内容。原文、韩文、角色或前后相关上下文改变时，旧确认会失效；路径或行号变化会作为新的对应关系处理。请从最新扫描结果重新复核，不修改表里的“对应标识”和“内容指纹”；导入失效、重复或非法记录时整次导入失败，已保存的复核不受影响。建议中的“人工确认可适用”和“可试合并”分别表示人工结论与程序定位证据，均不回填 `TextTrans`。拆分预览仍独立按下述规则生成。

历史 `story` 复核记录保留，但不会启用范围外的合并。含范围外候选的旧复核表不能重新导入，请使用最新的“复核填写”表更新 `char.xlsx` 对应结论。

复核记录保存失败时，撤回本次结果目录并保留旧复核，不留下包含未保存确认的成功报告。

试拆分优先使用数字编号，支持数字后的中英文分号、逗号、顿号以及已有的点号、冒号、括号。例如 `1；甲 2；乙` 可以对应 `1. 가 2. 나`。中韩须从1连续编号、顺序和段数一致；小数和千位分隔符不当作编号。

中文没有编号时，按实际或字面换行逐段对应韩语，中韩段数必须一致。韩语每段原值与编号保留，不调整韩语编号；只去掉两侧空白边缘行，内部空行、占位符不一致和跨段标签继续待复核。字母编号仍只列候选。

支持部分匹配：优先使用唯一的整组连续对应，否则逐段查找基准；只有唯一位置且没有其他源分段争用时输出预览。例如第2段没找到，第1、3段仍可输出，第三段保持对应第三段韩语。重复位置、来源冲突与未找到内容均保留具体原因。分段上限沿用“最多连续行数”，正文最多16000字符。

`试拆分结果.xlsx` 包含“拆分明细”“整组原文”“分段未匹配”“分段候选”“暂不拆分”“拆分说明”。“拆分明细”新增拆分规则、整组匹配情况；“暂不拆分”也包含部分匹配组的剩余问题，因此组数不能简单相加。试拆分仅供复核，不回填 `TextTrans`，不改动源文件或基准原件。连续整组候选与逐段定位分别统计，不代表同一种成功数量。

也可从命令行运行（沿用默认表头、默认扫描开关及本机忽略列表；自定义表头请用界面）：

```sh
python structure_scan.py "1_客户源文件" "0_基准文件" "outputs" --max-rows 8 --header-rows 10
```

### 检索并生成结果

1. 第一页选择 `1_客户源文件`，完成表头检查；异常 Sheet 会跳过，其他通过的 Sheet 可以继续检索。客户修正文件后需重新执行第一步，才能恢复此前异常的 Sheet。
2. 进入“第二步：译文检索”，选择 `0_基准文件` 和单独的输出文件夹。基准与源文件夹不能互相包含；输出不能放在这两个文件夹内部。
3. 点击“开始检索并生成结果”。完成后点击“打开结果文件夹”。每次生成独立的新目录，失败时删除本次临时结果，不留下看起来已完成的半成品。

基准文件支持 `.xlsx`、`.xlsm`，递归处理所有文件及工作表。在每张 Sheet 的前 N 个实际行号中查找唯一的 `Text` 表头，N 沿用第一页“检查行数”（默认 10，最低 1），从表头下一行开始检索该列中文。忽略表头名称首尾空白并规范化 Unicode，保留大小写，不做模糊匹配；`Text` 不必在 G 列或第 1 行。`TextTrans` 无论位于哪一列均保留原值，不作为匹配输入，也不自动覆盖；没有 `TextTrans` 仍可检索。找不到或找到多个 `Text` 时明确提示查找范围或候选单元格位置。当前第一步检查的规则会用于执行时复查，避免源文件后来改动表头仍被处理；第一步异常列表和本地忽略列表中的 Sheet 始终跳过。新发现的表头异常和正文读取失败也会跳过并列入结果清单。文件级异常整文件跳过。已忽略的表只读取名称确认存在，不读取正文或检查表头。

第一轮匹配规则：**只去除中文首尾空白后全文精确匹配**，不做模糊匹配，不改变内部空格、标点、换行或 Unicode 表示；空值、纯空白及非文本的中文不参与。源文件中的隐藏 Sheet 与隐藏行是否参与由开关控制。韩语为空的匹配也保留，方便发现缺译；同一中文在不同文件、Sheet 或行出现，都独立计数，不按相同译文去重。同一源行命中多个基准行，源文件统计仍只算一条。中韩正文为公式时明确跳过该 Sheet，并回滚该 Sheet 已读到的匹配，避免把公式当作文本或输出半张表的数据；请先将公式转成文本值。

源表同时存在“特殊说明”和“说话角色名”列时，两列值都为空的行视为无效说明，从整句匹配、上下文与匹配率分母中排除，保留在“上下文排除明细”。缺少任一表头时不套用这项清理。特殊说明规范化后恰为“气息”的源行，额外支持忽略双方中文成对的 `（…）` / `(…)` 后匹配；支持嵌套，不改变普通台词的括号，也不改写原中文或韩语。去括号后为空时不增加去括号候选；括号未闭合或配对错误时保留原文比较。特殊说明或需要判断的角色名单元格为公式、同名元数据列重复时，会跳过该 Sheet 并保留原因。

第二轮只处理第一轮仍未推荐的基准行，保留已经得到的精确推荐。两边中文及前后三句中的 `{playername}` 等成对花括号、`<color=#3266b4>` / `</color>` 等英文标签、实际 CR/LF 以及字面量 `\n` / `\r` 被移除后，去首尾空白并统一下述四组指定标点后全文匹配；保留其余文字、数字、标点、内部空格和 Unicode 表示，本轮不做模糊匹配。清理后为空的句子不参与补匹配，也不占补匹配上下文位置。

指定标点仅按四组等价：`…` 与 `...`、`，` 与 `,`、`;` 与 `；`、`：` 与 `:`。每个省略号对应三个半角点，`……` 对应六个点；不合并任意数量的点，也不扩大到叹号、问号、句号、字母或数字等全半角。两边清理后的全文相同，进入纯文本补匹配；只有一种非空韩语时状态为“唯一译文”，多译文继续按原有上下文规则判断，无法确定时待确认。推荐依据注明“比较时忽略指定标点差异”，输出原文与译文不做标点转换。此规则同时用于该阶段上下文、后续句尾补查及模糊评分；结构入口的整句检查也共用它，连续合并/拆分的段落比较仍沿用原规则。

补匹配仍沿用唯一译文、完整前3句或后3句一致、同分待确认等推荐规则，韩语种类仍按原值只去首尾空白比较。补推荐成功时，基准副本及匹配明细的“推荐依据”均包含 **仅纯文本匹配，仍需复核标签**。输出保留来源中韩原值及标签，只执行已有首尾换行规则，不自动改写占位符或标签。第一轮已推荐的基准不再加入仅标签不同的新来源。

全部阶段实际候选共同计入匹配统计；同一源行在多处命中仍只计一次。“匹配方式”列标明全文精确匹配、气息去括号匹配、纯文本补匹配、句尾去括号补匹配或模糊匹配；纯文本补匹配同时忽略气息括号时会在推荐依据注明。上下文及得分展示对应轮次实际使用的内容。未匹配、未推荐清单在补匹配结束后生成。源文件冲突统计仍按含标签和括号的原中文分组；基准冲突按该行实际候选判断，补匹配可能产生原中文分组之外的冲突。

`基准匹配结果/` 保留基准文件的相对目录和文件名，每张表的结果表头与识别出的 Text 表头在同一行。原表头未超过 Q 列时，结果仍为以下 R～AG 列；原表头延伸到 R 列或更右侧时，在其最后一个非空表头之后依次追加同样的 16 个字段，以结果表头名称为准：

- R、S、T：第 1 条匹配的中文、韩语（按基准处理首尾换行）、完整源文件路径 + Sheet 名 + 实际行号。
- U、V、W 和 X、Y、Z：第 2、3 条的同类内容。
- AA：匹配条数。0 表示未找到，1～3 条展开内容，超过 3 条只写条数，R～Z 留空。
- AB：匹配来源中缺译的行数；AC：是否存在译文冲突（是 / 否 / 未匹配）。超过 3 条的结果也保留这两项提示。
- AD：推荐韩语；AE：推荐来源（完整路径、Sheet、实际行号）；AF：推荐依据；AG：推荐状态。所有匹配条数都计算推荐，包括超过 3 条的情况。
- 所有原有列（包括 Text、TextTrans）保留。目标结果列如果已有内容或公式会明确停止，避免覆盖；带有已生成结果表头的基准文件也会拒绝重复回填。基准原件不保存，只输出副本。

输出换行按每个基准行的 Text 列原文判定：基准开头无换行，删除输出开头的换行；基准结尾无换行，删除输出结尾的换行。两侧分别处理，适用于 R/U/X 匹配中文、S/V/Y 匹配韩语与 AD 推荐韩语。换行包括 LF、CRLF、CR，以及夹在首尾空白中的换行；补删仅作用于首尾换行，保留空格、制表符和内部换行。基准某侧有换行时，来源该侧已有换行则原样保留，没有则在对应首尾补一个 LF；不统一已有换行的数量。空值与全空白译文不补换行。匹配、推荐排序、计数及冲突判断不变，明细中的源中文和韩语仍保留原值。

`源文件匹配统计.xlsx` 包含“文件统计”“Sheet统计”“跳过清单”。匹配率 = 命中任一基准中文的源行数 / 参与 Sheet 中非空文本中文行数；未匹配行数 = 分母 - 匹配行数。忽略、异常、正文读取失败的 Sheet 不计入分母。全部跳过或没有非空中文时匹配率留空，不伪装成 0%；“跳过清单”逐项说明原因。“文件统计”按文件合计，同时列出参与与跳过数量。

文件和 Sheet 统计新增“缺译行数”“冲突中文数”：前者统计该范围内非空中文对应的空韩语行数（包括未命中基准的源行）；后者统计该范围内出现过的冲突中文种类数。冲突判定跨全部参与的源文件和 Sheet；同一冲突中文出现在多个文件，各文件均计一次，整体冲突中文数不等于各文件简单相加。

`匹配明细.xlsx` 包含以下明细，可在窗口点击“打开匹配明细”：

- **匹配明细**：每个源行与每个命中的基准行各一项，同时列出基准文件、Sheet、行号和缺译 / 冲突标记；超过 3 条仍全部导出。每个匹配对应附上双方前后三句（实际行号及去首尾空白后的中文）、一致数、完整一致侧数、一致位置总数、是否为选中的推荐来源、推荐状态和依据。同一源行命中多个基准行时明细展开，明细数量可以大于源文件统计的匹配行数。
- **上下文排除明细**：列出两列均为空的无效说明，以及不计有效上下文句数的演出、气息行，包括中文为空的演出行。处理原因区分“整行排除”和“只不计上下文有效句”，气息原始括号说明仍可回查。
- **合并拆分推荐**：每个实际写入的结构推荐一项，列出目标位置、处理后韩语、全部来源、组ID、规则与待复核状态；基准副本另按目标原文对齐首尾换行。结构推荐按组计入匹配条数和推荐统计，源行按实际位置去重计入匹配统计。
- **结构推荐未写入**：记录因保留已有整句推荐或存在多组结构推荐而未写入的候选，未采用的结构候选不计入推荐数量。
- **未匹配明细**：逐行列出未命中任何基准中文的源行，并附缺译标记及韩语种类数。
- **缺译明细**：韩语为空值或全空白的源行，附是否命中基准。非空中文且韩语为空仍计为中文匹配成功，不从匹配率中删除。
- **译文冲突**：同一中文去除首尾空白后，对应至少两种不同的非空韩语。韩语比较也只去掉首尾空白，保留内部空格、标点、换行及 Unicode 表示；重复的相同译文不构成冲突，空韩语不算一种译文。逐行展开该中文的全部来源（包括其中的缺译行），并列出非空韩语种类数，供人工判断；该冲突标记仍保留，即使某个基准行已通过上下文得到推荐。
- **未推荐明细**：按“源中文＋韩语”判断是否已获推荐；两者分别去首尾空白后比较，保留内部空白、换行、标点、标签和括号差异。同文同译的来源只要有一条完整获推荐，其他重复来源也不再列入，适用于同 Sheet、跨 Sheet 和跨文件。结构入口生成的结果会排除实际用于合并、或全部分段都写入拆分推荐的源句；仅部分分段写入的源句仍保留，并注明“拆分后仅部分分段获推荐，剩余分段待复核”。有结构候选但因整句优先或结构竞争未写入时，注明“结构候选未写入”及原因；其他源行保留“基准文件中找不到”和“基准文件中找到了但不符合推荐规则”两类原因。独立预览中尚未实际写入的候选不作已推荐处理；完全没有推荐的重复来源仍逐行保留。忽略、异常、正文读取失败及开关排除的内容不列入；无记录时保留表头。

### 句尾括号补匹配

前两轮都没有进入任何实际候选的源句，再去掉句尾成对的中英文括号及内容，按纯文本规则重新查找全部基准。支持连续、嵌套括号；句中括号不删，异常括号不猜测，清理后为空不参与。例如源句“你好（小声）”可补匹配基准“你好”，原始中文、韩语及标签保留。

已有推荐保持不变，新增来源列入明细与覆盖统计，依据注明保留先前推荐；尚未推荐时，新旧候选共同按原推荐规则竞争。推荐方式标为“句尾去括号补匹配”时，依据注明忽略源中文句尾括号说明及“仅纯文本匹配，仍需复核标签”。先前已命中过其他基准的源句不重复参加本轮。

### 上下文推荐

源文件正文只读一次，所有基准文件共享同一个磁盘索引；逐个基准文件输出副本并单独统计。每个基准行独立选择推荐，同一句中文在不同段落可以推荐不同韩语。

上下文取同一文件、同一 Sheet 内当前句前后各 **3 条有效中文台词**，不跨 Sheet，也不按句号拆句。向外逐行检查，遇到特殊说明恰为“演出”或“气息”的行不计有效句，继续向外补查；新增行同样检查，直到各侧取得3条有效台词或到达 Sheet 边界。中文为空的演出、气息行仍计入查询及特殊行数量。普通空白、非文本中文、已清理的无效说明及按开关排除的行不参与；韩语为空但中文有效的普通台词仍参与。“奇波”“演出说明”等其他标记不跳过。

若演出或气息的中文也与基准当前邻句一致，则同步越过双方的位置；气息比较忽略成对括号说明。否则只越过源行，不消耗基准邻句。剩余有效台词按前1句对前1句、后1句对后1句逐位置比较；普通台词不一致时，不继续向外搜索来替换它。边界处不足3句不凑数。该规则同时用于全文和纯文本两轮。

“匹配明细”末尾新增“完美匹配”“上下文跳过位置”“上下文查询统计”。最后一列在同一单元格分别列出向上、向下及合计的查询行数、演出行数、气息行数、有效匹配句数，**不含当前句，不累计多轮重复检查**；查询数包含特殊行，匹配数只计有效台词，最多上下各3句。例如“合计（不含当前句）：查询10行，演出2行，气息2行，匹配6句”。跳过位置显示源实际行号及是否同时越过基准行。

- 所有非空韩语去首尾空白后只有一种时，标为“唯一译文”，直接推荐；空译文不影响这一结论。
- 存在不同译文时，候选得分按“完整一致侧数、一致位置总数”从大到小比较。双方某侧都存在 3 句且全部一致才算完整一致侧。前后都完整一致优于只有一侧完整一致；同为一侧完整一致时，另一侧一致位置更多的优先。
- 只有向上、向下各3条有效台词都一致，才标为“完美匹配”。这是逐候选的上下文证据，不等于一定推荐：不同译文同时完美匹配仍待确认，缺译候选也不会被选中。唯一译文或单侧完整一致可以沿用已有推荐规则，但推荐依据会注明非完美匹配。
- 最高分候选必须至少有完整一侧一致，且只对应一种非空韩语，才标为“上下文推荐”。不同韩语并列或只有不足 3 句的部分证据时，标为“待确认”，推荐韩语与来源留空。
- 相同译文有多个同分来源时，取读取顺序最早的源行；源文件按路径排序、Sheet 按工作簿顺序、行按实际行号读取。推荐保留该来源韩语原值，仅按基准补删首尾换行。
- 无中文命中标为“未匹配”；有中文命中但所有韩语为空标为“全部缺译”。推荐仅是上下文规则的建议，保留全部候选与冲突信息供确认。

### 基准文件汇总

`基准文件匹配统计.xlsx` 包含“文件统计”“Sheet统计”“总体统计”，以 **基准非空中文行**为计数单位，同一中文重复出现逐行计数。每个文件即使零命中或无有效中文也列出，不按文件名合并，完整路径区分同名文件。

各表列出：非空中文行数、中文匹配行数、有译文行数、推荐行数、未匹配行数、命中但全缺译行数、冲突行数、冲突已推荐行数、冲突待确认行数，以及中文匹配率、译文覆盖率、推荐率。三个比率分别为中文匹配行数、有译文行数、推荐行数除以非空中文行数；分母为零时留空。总体统计按各文件的行数相加后重新计算比率，不平均文件比率。

中文命中与取得韩语分别统计：命中但全部缺译不算有译文；存在冲突但尚未推荐仍算有译文。一个源行命中 100 个基准行时，基准统计可计 100 行，源文件统计只计该源行一次。匹配明细按实际对应关系展开。

各类明细只来自本次参与且正文完整读取成功的 Sheet，忽略、异常和开关排除的内容均不参与。无对应数据时只保留表头；超过 Excel 单张表 1,048,576 行时自动拆分为带编号的后续 Sheet。明细以只写模式逐行输出，不在内存汇总全部结果。

基准中文集合、行位置与匹配索引存放于本地临时 SQLite 数据库；源正文逐文件、逐 Sheet 以只读模式读取，限定中韩列所在的列范围，不把所有正文读入内存。Excel 的 XML 仍需顺序解析，并非磁盘层面只读取两列。基准副本也逐行输出工作表 XML，其他 ZIP 内部文件原样复制，保留原有格式、公式、图片与宏，不整本加载基准文件。Excel 共享字符串和样式仍可能占用内存，不承诺任意文件固定内存。临时数据库在完成或失败后删除。后台执行期间窗口可响应，关闭需等待任务结束。

## Windows exe

### 程序内更新

从 v1.1.0 起，Windows exe 启动时后台查询 GitHub 最新正式 Release；右上角显示当前版本，也可点击“检查更新”。发现新版本后由用户确认，自动下载、校验文件大小及 SHA256，关闭旧程序、替换 exe 并重启。扫描、检索或下载期间禁止安装更新；后台检查不影响正在运行的任务，发现更新后可以等任务结束再点击更新。

从 v1.1.1 起通过最新 Release 的 `update.json` 查询版本、固定版本下载地址、文件大小与 SHA256，避开 GitHub API 匿名限流。网络不通时扫描仍可使用。下载或校验失败不修改旧程序；替换与启动失败时尝试恢复备份。更新目录需有当前用户写权限；本地设置、忽略记录、客户源文件和检索结果均保留。macOS 开发版可检查版本，自动替换仅支持 Windows 打包 exe。以前没有更新功能的 exe 需要手动更换一次。

从 v1.1.7 起，每个通道最多尝试两次；主通道网络失败后改用本仓库 `updates` 分支的备用地址（raw.githubusercontent.com），分别支持更新清单和固定版本 exe。两个通道使用相同的文件大小和 SHA256 校验，不使用第三方代理。连接和读取中断均从头重试；两条通道都失败时提示更换网络。旧版不认识备用通道，首次需手动替换成新版；备用主机也可能受客户网络限制，仍需在客户电脑验证。

客户无需 GitHub 账号，正式下载入口为 [最新发布版本](https://github.com/tyrtrtz/translate-scaner/releases/latest)。本程序仅请求版本信息和下载 exe，不上传客户文件。

发布新版本时，修改 `updater.py` 中的 `VERSION`（例如 `1.1.7`），更新 `docs/发布说明.md`，提交推送后创建同名标签：

```sh
git tag v1.1.7
git push origin v1.1.7
```

标签触发 Windows 测试、打包和启动检查，通过后自动生成更新清单、发布 GitHub Release，并将校验一致的 exe 与清单推送到独立 updates 分支。版本目录不覆盖不同内容，保留历史版本，最新清单不会因发布旧版本而降级；标签版本必须与程序版本完全一致。普通 main 推送继续生成测试构建产物，不作为正式客户端更新。客户端使用 [GitHub 官方的最新发布文件直链](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases) 下载更新清单。

### GitHub Actions

上传程序源码和 `.github/workflows/build-windows.yml` 后，推送到 `main` 或 `master` 会自动触发 **Build Windows exe**，也可在 Actions 页面手动点击 **Run workflow**。

CI 使用 Windows x64 和 Python 3.13，依次安装打包依赖、运行测试、生成单文件 exe、验证打包后的窗口可以启动，然后上传构建产物。

普通分支构建成功后，在该次运行页面的 **Artifacts** 下载 **HeaderChecker-Windows-x64**，解压得到 `HeaderChecker.exe`。正式版本在 **Releases** 直接提供 exe，并供程序内更新下载。客户双击即可使用，无需安装 Python。Artifacts 构建产物保留 30 天；正式 Release 不受此限制。

客户资料、Excel 文件、需求文档、导出清单、本地设置和忽略记录均已加入 `.gitignore`；构建只依赖源码，不需要这些文件。

### 在 Windows 本机打包

在 **Windows 电脑或 Windows 虚拟机**上安装 Python（包含 Tkinter 和 `py` 启动器），双击 `build-windows.cmd`。脚本创建环境、安装依赖、运行测试，再生成 `dist\HeaderChecker.exe`。将 exe 发给客户，客户无需安装 Python。打包阶段需要联网安装依赖。

macOS 上可以开发和测试，但不能直接用 PyInstaller 生成 Windows exe。需在 Windows 上构建，并验证启动、中文/韩语路径、文件夹选择和 Excel 打开 CSV。见 [PyInstaller 官方平台说明](https://pyinstaller.org/en/stable/operating-mode.html)。
