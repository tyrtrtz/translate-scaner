# 中韩表头检查与译文检索

第一步检查客户源文件的中韩表头，列出异常供客户处理；第二步按基准中文检索译文，输出基准匹配副本和源文件匹配率统计。源文件和基准原件均不会被修改。

## 使用

安装 Python 3.10 或以上（需包含 Tkinter），在项目目录运行：

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

Windows 开发环境将前两条替换为 `py -3 -m venv .venv` 和 `.venv\Scripts\activate`。

选择 **1_客户源文件**，不要选择同时包含基准文件的上级目录。根据需要调整表头名称和检查行数，点击“开始检查”。双击异常项（或选中后按 Enter）可查看可滚动的检查依据，包括允许的表头名称、已找到的位置、顶部及候选表头行的实际文本样例，以及同文件中已通过的工作表。也可打开所选文件所在文件夹。点击“导出异常清单”保存 CSV，Windows Excel 可以直接打开，中文和韩语采用 UTF-8 BOM 编码。

## 批量忽略 Sheet

在“异常列表”最左侧点击方框逐项勾选，可直接选择不相邻的 Sheet，也可以点击“勾选全部”或“取消勾选”，然后点击“忽略勾选 Sheet”。查看、双击其他行不会改变已有勾选；键盘聚焦某一行后按空格也可以切换勾选。保存成功后，这些 Sheet 立即从当前异常列表、异常数量和导出清单中移除；后续检查在表头检查之前直接跳过它们，不生成错误，也不计入通过数量。源文件及其中的 Sheet 不会被修改。

“已忽略列表”显示本机保存的所有忽略记录，也支持逐项勾选、勾选全部和取消勾选。点击“移除勾选忽略记录”后，重新检查即可恢复处理这些 Sheet。恢复时会清空旧检查结果，避免导出仍然缺少这些 Sheet 的旧清单。

忽略范围是 **文件完整路径 + Sheet 名称**，不影响其他文件里的同名 Sheet；文件或 Sheet 改名、移动后需要重新设置忽略。找不到 Sheet 名称的文件级读取失败或不支持格式记录不能按 Sheet 忽略。

记录会自动保存，重启程序仍然有效；界面“已忽略列表”中显示记录文件位置：

- macOS：`~/Library/Application Support/HeaderChecker/ignored_sheets.json`
- Windows：`%LOCALAPPDATA%\HeaderChecker\ignored_sheets.json`（没有 LOCALAPPDATA 时使用 APPDATA）
- Linux：`$XDG_CONFIG_HOME/HeaderChecker/ignored_sheets.json`，默认 `~/.config/HeaderChecker/ignored_sheets.json`

记录保存失败时保留原有列表，不会假装已忽略；记录文件损坏时明确提示并禁用检查，修复后重启，避免忽略设置静默失效。命令行入口也会读取同一份本地记录。

## 保存使用设置

源文件夹、基准文件夹、输出文件夹、自定义中韩表头、检查行数及三个扫描开关会在点击检查、点击检索和正常关闭窗口时自动保存，也可点击“保存设置”立即保存。重启后恢复设置，但不恢复旧检查结果，仍需先检查再检索。

设置保存在忽略记录同一目录下的 `settings.json`，与 `ignored_sheets.json` 分开，不影响已有忽略记录。采用临时文件加原子替换，保存失败或输入无效会提示，保留原有设置；设置损坏时使用默认设置并停用保存，明确提示修复文件后重启，不覆盖损坏原件。文件夹暂时不存在不会阻止启动，在检查或检索时再验证。

## 检查规则

- “扫描子文件夹”“扫描隐藏工作表”“扫描隐藏行”三个开关默认全部开启。关闭子文件夹扫描时只处理所选目录第一层；关闭隐藏工作表扫描时不检查 hidden / veryHidden Sheet；关闭隐藏行扫描时不使用 Excel 标记为 hidden 的行，包括筛选后标记隐藏的行。表头行若被隐藏且开关关闭，也不会用于识别。忽略 Excel 的 `~$` 临时文件和非表格文件。
- 第二步检索与源文件匹配率统计沿用第一步的三个开关；修改开关后需重新执行第一步。按开关跳过的隐藏 Sheet 不作为异常，但会列在匹配输出的“跳过清单”中。基准文件的格式固定，基准所有工作表和 G 列行仍按固定格式处理。
- `.xls`、`.xlsb`、`.ods` 会列为不支持格式，需客户转存为 `.xlsx`。
- 默认检查每张工作表前 **10 个实际行号**。行数输入框支持自行输入大于等于 1 的整数；不是前 10 个非空行，超出范围的表头需要增大行数后重新检查。
- 默认中文表头：对白文本、台词、文本内容（示例）、语音、最新(2.18)、中文原文；韩语表头：韩文、한국어、韩语译文。界面可增删名称，每行一个；设置会保存在本机。
- 采用完整名称匹配，忽略首尾空白并进行 Unicode NFKC 规范化，兼容全角括号和韩语组合字符。不猜测无表头的列，不按正文语言自动识别。
- 中文和韩语表头必须在同一行，且该行各有唯一候选列。找到多个共同表头行或候选列时列为异常。同一合法表头行之外的零散关键词不作为额外候选列。
- 尚未忽略的参考表、封面、修改记录等没有中韩表头时会列为“需确认是否为翻译表”，可在异常列表确认后批量忽略。异常数量不等于需要修改的翻译表数量。
- 文件损坏、加密或无法读取时列入异常，不会将其当作通过。某个文件失败不会阻止其他文件检查。
- 通过仅表示在指定范围内找到明确表头，不表示正文内容、译文质量或后续匹配已经验证。

异常 CSV 每项一行，包含文件名、相对路径、完整路径、工作表、显示状态、具体异常原因、中韩候选表头的位置、检查范围、检查依据和该文件已通过的工作表。无异常时导出只有列名的清单。

异常原因会区分缺少中文表头、缺少韩语表头、两者均未找到、检查范围内无非空内容、不同表头行和多个候选列。只缺少其中一种时会明确给出另一种的已识别位置。文本样例取顶部 3 个非空行及最多 3 个候选表头行，每行最多 32 项、每项最多 80 字；这是人工判断的证据，不意味着自动确认这些内容就是表头。未找到时只能说明检查范围内没有名称匹配，不能据此确定整张表没有译文或一定属于参考表。

## 大文件处理

逐个文件以 openpyxl 只读模式打开，只遍历指定的头部行，不加载图片，也不把所有正文汇总到内存。每个文件检查完成即关闭。共享字符串和样式仍可能占用内存，不承诺任意文件固定内存；根据客户样本实测。

## 第二步：译文检索

1. 第一页选择 `1_客户源文件`，完成表头检查；异常 Sheet 会跳过，其他通过的 Sheet 可以继续检索。客户修正文件后需重新执行第一步，才能恢复此前异常的 Sheet。
2. 进入“第二步：译文检索”，选择 `0_基准文件` 和单独的输出文件夹。基准与源文件夹不能互相包含；输出不能放在这两个文件夹内部。
3. 点击“开始检索并生成结果”。完成后点击“打开结果文件夹”。每次生成独立的新目录，失败时删除本次临时结果，不留下看起来已完成的半成品。

基准文件支持 `.xlsx`、`.xlsm`，递归处理所有文件及工作表。格式固定为第 1 行表头，G1 为 `Text`，从 G2 开始检索中文。当前第一步检查的规则会用于执行时复查，避免源文件后来改动表头仍被处理；第一步异常列表和本地忽略列表中的 Sheet 始终跳过。新发现的表头异常和正文读取失败也会跳过并列入结果清单。文件级异常整文件跳过。已忽略的表只读取名称确认存在，不读取正文或检查表头。

匹配规则：**只去除中文首尾空白后全文精确匹配**，不做模糊匹配，不改变内部空格、标点、换行或 Unicode 表示；空值、纯空白及非文本的中文不参与。源文件中的隐藏 Sheet 与隐藏行是否参与由开关控制。韩语为空的匹配也保留，方便发现缺译；同一中文在不同文件、Sheet 或行出现，都独立计数，不按相同译文去重。同一源行命中多个基准行，源文件统计仍只算一条。中韩正文为公式时明确跳过该 Sheet，并回滚该 Sheet 已读到的匹配，避免把公式当作文本或输出半张表的数据；请先将公式转成文本值。

`基准匹配结果/` 保留基准文件的相对目录和文件名，每张表：

- R、S、T：第 1 条匹配的原始中文、韩语、完整源文件路径 + Sheet 名 + 实际行号。
- U、V、W 和 X、Y、Z：第 2、3 条的同类内容。
- AA：匹配条数。0 表示未找到，1～3 条展开内容，超过 3 条只写条数，R～Z 留空。
- AB：匹配来源中缺译的行数；AC：是否存在译文冲突（是 / 否 / 未匹配）。超过 3 条的结果也保留这两项提示。
- P、Q 与原有 A～O 列不改动；R～AC 如果已有内容会明确停止，避免覆盖既有结果。基准原件不保存，只输出副本。

`源文件匹配统计.xlsx` 包含“文件统计”“Sheet统计”“跳过清单”。匹配率 = 命中任一基准中文的源行数 / 参与 Sheet 中非空文本中文行数；未匹配行数 = 分母 - 匹配行数。忽略、异常、正文读取失败的 Sheet 不计入分母。全部跳过或没有非空中文时匹配率留空，不伪装成 0%；“跳过清单”逐项说明原因。“文件统计”按文件合计，同时列出参与与跳过数量。

文件和 Sheet 统计新增“缺译行数”“冲突中文数”：前者统计该范围内非空中文对应的空韩语行数（包括未命中基准的源行）；后者统计该范围内出现过的冲突中文种类数。冲突判定跨全部参与的源文件和 Sheet；同一冲突中文出现在多个文件，各文件均计一次，整体冲突中文数不等于各文件简单相加。

`匹配明细.xlsx` 包含四类明细，均列出原始中文、韩语、文件完整路径、Sheet 和实际行号，可在窗口点击“打开匹配明细”：

- **匹配明细**：每个源行与每个命中的基准行各一项，同时列出基准文件、Sheet、行号和缺译 / 冲突标记；超过 3 条仍全部导出。同一源行命中多个基准行时明细展开，明细数量可以大于源文件统计的匹配行数。
- **未匹配明细**：逐行列出未命中任何基准中文的源行，并附缺译标记及韩语种类数。
- **缺译明细**：韩语为空值或全空白的源行，附是否命中基准。非空中文且韩语为空仍计为中文匹配成功，不从匹配率中删除。
- **译文冲突**：同一中文去除首尾空白后，对应至少两种不同的非空韩语。韩语比较也只去掉首尾空白，保留内部空格、标点、换行及 Unicode 表示；重复的相同译文不构成冲突，空韩语不算一种译文。逐行展开该中文的全部来源（包括其中的缺译行），并列出非空韩语种类数，供人工判断，不自动选择译文。

四类明细只来自本次参与且正文完整读取成功的 Sheet，忽略、异常和开关排除的内容均不参与。无对应数据时只保留表头；超过 Excel 单张表 1,048,576 行时自动拆分为带编号的后续 Sheet。明细以只写模式逐行输出，不在内存汇总全部结果。

基准中文集合、行位置与匹配索引存放于本地临时 SQLite 数据库；源正文逐文件、逐 Sheet 以只读模式读取，限定中韩列所在的列范围，不把所有正文读入内存。Excel 的 XML 仍需顺序解析，并非磁盘层面只读取两列。基准副本也逐行输出工作表 XML，其他 ZIP 内部文件原样复制，保留原有格式、公式、图片与宏，不整本加载基准文件。Excel 共享字符串和样式仍可能占用内存，不承诺任意文件固定内存。临时数据库在完成或失败后删除。后台执行期间窗口可响应，关闭需等待任务结束。

## Windows exe

### GitHub Actions

上传程序源码和 `.github/workflows/build-windows.yml` 后，推送到 `main` 或 `master` 会自动触发 **Build Windows exe**，也可在 Actions 页面手动点击 **Run workflow**。

CI 使用 Windows x64 和 Python 3.13，依次安装打包依赖、运行测试、生成单文件 exe、验证打包后的窗口可以启动，然后上传构建产物。

构建成功后，在该次运行页面的 **Artifacts** 下载 **HeaderChecker-Windows-x64**，解压得到 `HeaderChecker.exe`。客户双击即可使用，无需安装 Python。构建产物保留 30 天；需要时可重新触发构建。

客户资料、Excel 文件、需求文档、导出清单、本地设置和忽略记录均已加入 `.gitignore`；构建只依赖源码，不需要这些文件。

### 在 Windows 本机打包

在 **Windows 电脑或 Windows 虚拟机**上安装 Python（包含 Tkinter 和 `py` 启动器），双击 `build-windows.cmd`。脚本创建环境、安装依赖、运行测试，再生成 `dist\HeaderChecker.exe`。将 exe 发给客户，客户无需安装 Python。打包阶段需要联网安装依赖。

macOS 上可以开发和测试，但不能直接用 PyInstaller 生成 Windows exe。需在 Windows 上构建，并验证启动、中文/韩语路径、文件夹选择和 Excel 打开 CSV。见 [PyInstaller 官方平台说明](https://pyinstaller.org/en/stable/operating-mode.html)。
